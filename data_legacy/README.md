# data_legacy/

Stale artifacts moved out of `data/` during the 2026-08 pipeline reorganisation
(module renames + cM05 canonicalisation + relocation of the cluster-level sorting
annotation into Module A). Kept — not deleted — in case an intermediate is needed.

**Nothing in the active four-module pipeline (`module0_ld_pruning`,
`moduleA_sorting`, `moduleB_climate_GEA`, `moduleC_climate_vs_sorting`) reads from
here.** Those modules read their upstream siblings' `data/` folders and the five
shared inputs still in `data/`.

> **Moved back out (2026-08-04):** `results_min_loci5.rds` (the ≥5-marker eMLG
> construction sweep) was moved to its canonical home `module0_ld_pruning/data/`,
> where `module0_ld_pruning/R/module0_fig_fidelity_hist.R` reads it to build the
> consensus-fidelity figure (manuscript Fig S6).

`moduleA_cM1/` holds Module A's caches built on the **old cM1** clustering, cleared
so the cM05 rerun starts clean (moduleA's `cache_rds` keys on sorting params, not
the clustering, so a warm rerun would otherwise silently reuse them). All are
regenerated by rerunning Module A on cM05.

The top-level files here are old-scheme copies (pre-reorg) of Module A/B/C outputs, superseded
clustering objects (`eMLG_5loci_0025_rho095.rds`, `eMLG_groups.rds`, old
`eMLG_sorted_cM05.rds`, `pruned_markers.rds`), old sensitivity/enrichment tables,
and one malformed filename (`datald_decay_DI.rds`, a `paste0` bug — the correct
object is `module0_ld_pruning/data/ld_decay_DI.rds`).
